| --------- | --------------------------------- |
| 버전      | v0.1 (초안)                       |

> 이 문서는 화면·API가 따라야 할 **세부 운영 규칙의 정본**입니다. PRD와 충돌하면 PRD가 우선하고, 이 문서에서 확정한 내용 중 PRD 범위를 바꾸는 것은 PRD Decision Log에 반영합니다.

## 1. 표기와 용어

### 1.1 항목 표기

| 표기     | 의미                                               |
| -------- | -------------------------------------------------- |
| `[확정]` | PRD에서 결정된 규칙. 근거를 함께 적음              |
| `[제안]` | 이 문서에서 추천하는 안. 검토 후 `[확정]`으로 전환 |
| `[미결]` | 선택지만 정리. 결정 필요                           |
| ⚠️ PRD   | 확정 시 PRD 수정이 필요한 항목                     |

### 1.2 용어

| 용어                  | 정의                                                         |
| --------------------- | ------------------------------------------------------------ |
| 리그                  | 구장을 구분하는 단위. 구장은 리그 하나에만 소속 (D10)        |
| 구장                  | 경기가 열리는 장소. 관리자 승인된 구장만 경기 개설에 사용    |
| 경기                  | 주최자가 개설한 1회의 용병경기                               |
| 예약                  | 용병이 경기의 포지션 1자리를 잡은 기록. 상태(PRD 6장)를 가짐 |
| 활성 예약             | `RESERVED` / `PAYMENT_SUBMITTED` / `APPROVED` 상태의 예약    |
| 경기 시작 / 종료 시각 | 주최자가 개설 시 입력한 시작·종료 시각 (6.1)                 |

## 2. 계정·역할

### 2.1 가입 `[확정]`

- 카카오 로그인만 지원합니다. 계정 1개에 역할을 부여합니다 (PRD 7.2).
- 최초 로그인 시 선수 카드 입력 화면으로 이동합니다. 필수 항목을 채우기 전에는 예약할 수 없고, 경기 탐색은 가능합니다 `[제안]`.

### 2.2 역할 부여

| 역할   | 부여 방식                                                                          |
| ------ | ---------------------------------------------------------------------------------- |
| 용병   | 가입 시 기본 부여 `[확정]`                                                         |
| 주최자 | `[제안]` **주최자 신청 → 관리자 승인**. 신청 시 연락처와 운영하는 리그·구장을 입력 |
| 관리자 | DB에서 직접 부여 (화면 없음) `[제안]`                                              |

- 근거: 주최자는 다른 사용자에게 돈을 받는 역할이라, 경기 개설만으로 송금을 유도하는 사기 위험이 있습니다. 베타 기간 주최자는 5~10명이라 수동 승인 부담도 작습니다.
- 주최자도 용병 기능을 모두 쓸 수 있습니다 (다른 경기 예약 가능) `[제안]`.

### 2.3 휴대폰 번호 (알림톡 수신)

- `[제안]` **카카오 로그인의 전화번호 동의항목**을 사용합니다. 알림톡 때문에 사업자 등록은 어차피 해야 하므로(D11) 비즈앱 전환의 추가 부담이 작고, 별도 SMS 인증 비용이 들지 않습니다.
- 동의를 거부하거나 받지 못하면 선수 카드에서 번호를 직접 입력하게 합니다. 이 경우 번호 인증은 MVP에서 생략합니다.
- 번호가 없는 사용자는 알림톡을 받지 못한다는 안내를 보여줍니다.

### 2.4 정지 계정 `[제안]`

- 로그인은 가능하고, 정지 사유와 이의제기 방법을 안내합니다.
- 새 예약과 경기 개설은 막습니다.
- 정지 시점에 이미 있는 활성 예약은 유지합니다. 강제로 취소하면 주최자 쪽 인원이 갑자기 빠지기 때문입니다.

### 2.5 탈퇴 `[미결]`

- 노쇼 이력을 지우려고 탈퇴 후 재가입하는 경우를 어떻게 막을지 결정해야 합니다.
- 선택지:
  - A. 탈퇴 즉시 모든 정보 삭제
  - B. 카카오 회원번호의 해시와 노쇼 횟수만 일정 기간 보관
- B를 택하면 개인정보 처리방침에 보관 사실을 명시하고 법률 검토가 필요합니다.

## 4. 급수 체계 `[제안]`

사회인야구에서 일반적으로 쓰는 "부" 단위를 그대로 씁니다. 숫자가 작을수록 상위 수준입니다.

| 값       | 표시        |
| -------- | ----------- |
| `DIV_1`  | 1부         |
| `DIV_2`  | 2부         |
| `DIV_3`  | 3부         |
| `DIV_4`  | 4부         |
| `ROOKIE` | 루키 (입문) |

- 선수 출신 여부는 급수와 별도로 체크박스로 받습니다 `[제안]`.
- **경기의 급수 필터는 "허용 급수 다중 선택"** 방식입니다.
  - 예: "4부 이하"는 4부와 루키를 선택한 것과 같습니다.
  - "N부 이하"처럼 문장으로 표현하면 위아래 해석이 엇갈려 오해가 생기기 쉬우므로, 화면에는 허용 급수를 칩으로 나열합니다.
- 선수 출신 참가 허용 여부도 경기 단위로 설정합니다 `[제안]`.
- 지역마다 급수 명칭이 다를 수 있으니, 0단계 리그 조사 때 목록을 확인합니다 `[미결]`.

## 5. 포지션 목록 `[제안]`

| 코드                | 표시                           |
| ------------------- | ------------------------------ |
| `SP`                | 선발투수                       |
| `RP`                | 구원투수                       |
| `C`                 | 포수                           |
| `1B` `2B` `3B` `SS` | 1루수 · 2루수 · 3루수 · 유격수 |
| `LF` `CF` `RF`      | 좌익수 · 중견수 · 우익수       |
| `DH`                | 지명타자                       |

- 주최자는 필요한 포지션에만 정원(1명 이상)을 설정합니다. 정원이 0인 포지션은 화면에 표시하지 않습니다.
- "포지션 무관(UT)" 슬롯은 MVP에서 두지 않습니다 `[제안]`. 이유는 두 가지입니다.
  - P0-3이 포지션을 명확히 지정하는 예약을 전제로 합니다.
  - 동시성 처리 대상인 슬롯이 단순해집니다.

## 6. 경기

### 6.1 개설 입력

| 항목          | 규칙                                                              |
| ------------- | ----------------------------------------------------------------- |
| 리그 → 구장   | 승인된 구장만 선택 가능 `[확정]` (D2, D10)                        |
| 시작 시각     | 개설 시점 기준 **최소 3시간 이후** `[제안]`                       |
| 종료 시각     | 필수. 시작 후 1~6시간 범위, 기본값은 시작 + 3시간 `[제안]` ⚠️ PRD |
| 참가비        | 0~100,000원, 1,000원 단위 `[제안]`                                |
| 허용 급수     | 1개 이상 선택 (4장)                                               |
| 포지션별 정원 | 1개 포지션 이상, 각 1~5명 `[제안]`                                |
| 입금 계좌     | 은행·계좌번호·예금주. 주최자 프로필에 저장해 다음 개설 때 재사용  |
| 안내 사항     | 선택. 500자 이내 (준비물, 주차 등)                                |

- **종료 시각이 필요한 이유:** 같은 시간대 예약 차단(7.2)과 경기 후 처리를 열 시점(10.1)을 판정하려면 종료 시각이 있어야 합니다. 현재 PRD P0-1에는 이 항목이 없으므로 추가가 필요합니다.

### 6.2 수정 `[제안]`

- 활성 예약이 **없으면** 모든 항목을 수정할 수 있습니다.
- 활성 예약이 **있으면** 아래만 수정할 수 있습니다.
  - 안내 사항
  - 포지션 정원: 늘리기만 가능하고, 줄일 때는 현재 빈자리 수만큼만 줄일 수 있습니다.
- 일시, 구장, 참가비, 계좌를 바꿔야 하면 경기를 취소하고 새로 개설합니다. 이미 입금한 사람의 조건이 바뀌는 것을 막기 위해서입니다.

### 6.3 경기 상태 `[제안]` ⚠️ PRD

PRD에는 예약 상태만 있고 경기 상태가 없습니다. 아래 상태를 추가하는 것을 제안합니다.

| 상태        | 조건                                                                                   |
| ----------- | -------------------------------------------------------------------------------------- |
| `OPEN`      | 모집 중. 빈자리가 있고 예약 마감 전                                                    |
| `FULL`      | 모든 포지션 정원이 잠김 (빈자리가 다시 생기면 `OPEN`으로 복귀) — 화면 표시용 파생 상태 |
| `CLOSED`    | 예약 마감 시각이 지남 (7.4)                                                            |
| `FINISHED`  | 종료 시각이 지남. 경기 후 처리 가능                                                    |
| `CANCELLED` | 주최자가 경기를 취소함 (D6)                                                            |

## 7. 예약

### 7.1 기본 규칙 `[확정]` (PRD P0-3)

- 한 경기에 1개 포지션만 예약할 수 있습니다.
- 예약 시 입금자명을 반드시 입력합니다.
- 마지막 1자리를 여러 명이 동시에 예약하면 1명만 성공합니다.

### 7.2 예약 차단 조건

| 조건                                    | 안내 메시지 (예시)                        | 근거          |
| --------------------------------------- | ----------------------------------------- | ------------- |
| 선수 카드 필수 항목 미입력              | "선수 카드를 먼저 완성해 주세요"          | 2.1 `[제안]`  |
| 정지된 계정                             | "계정이 정지되어 예약할 수 없어요"        | 2.4 `[제안]`  |
| 허용 급수가 아님                        | "이 경기는 ○부·○부만 참가할 수 있어요"    | P0-1 `[확정]` |
| 선수 출신 불허 경기                     | "이 경기는 선수 출신 참가가 제한돼요"     | 4장 `[제안]`  |
| 해당 포지션 정원이 참                   | "이 포지션은 마감됐어요"                  | P0-3 `[확정]` |
| 같은 경기에 활성 예약이 있음            | "이미 이 경기에 예약했어요"               | P0-3 `[확정]` |
| **같은 시간대에 다른 활성 예약이 있음** | "같은 시간대에 ○○리그 경기 예약이 있어요" | P0-3 `[확정]` |
| 예약 마감 시각이 지남                   | "예약이 마감됐어요"                       | 7.4 `[제안]`  |
| 본인이 주최한 경기                      | "내가 연 경기는 예약할 수 없어요"         | `[제안]`      |

- **같은 시간대의 정의** `[제안]`: 두 경기의 [시작, 종료] 구간이 1분이라도 겹치면 같은 시간대로 봅니다. 이동 시간 여유는 MVP에서 두지 않습니다.

### 7.3 재예약 `[제안]`

| 이전 예약의 결과                   | 같은 경기에 다시 예약          |
| ---------------------------------- | ------------------------------ |
| `CANCELLED` (본인 취소)            | 가능                           |
| `EXPIRED` (미입금·미승인으로 만료) | 가능                           |
| `REJECTED` (주최자 거절)           | **불가**. 주최자의 의사를 존중 |

### 7.4 예약 마감 `[제안]` ⚠️ PRD

- 예약 마감은 **경기 시작 2시간 전**입니다. 마감 후에는 새 예약을 받지 않습니다.
- 마감 전에 잡혀 있던 기존 예약의 입금·승인 처리는 계속 진행됩니다.

### 7.5 입금자명 `[제안]`

- 2~20자.
- 기본값으로 카카오 실명이나 닉네임을 미리 채우지 않습니다. 실제 이체할 명의를 직접 쓰게 하려는 것입니다.
- 화면에 "가족 명의로 이체하면 그 이름을 적어주세요"라는 안내를 보여줍니다. 입금자명 불일치를 줄이기 위한 문구입니다 (D13).

## 8. 시간 규칙

| 규칙                   | 값                                                                   | 상태                                               |
| ---------------------- | -------------------------------------------------------------------- | -------------------------------------------------- |
| 입금 완료 체크 기한    | 예약 후 24시간. **단, 경기 시작이 더 빠르면 경기 시작 시각까지**     | 24h `[확정]` P0-5 / 경기 시작 상한 `[제안]` ⚠️ PRD |
| 만료 전 알림           | 만료 12시간 전, 1시간 전. 남은 시간이 그보다 짧으면 해당 알림은 생략 | `[확정]` P0-10 / 생략 규칙 `[제안]`                |
| 승인 방치 리마인드     | `PAYMENT_SUBMITTED` 후 4시간 (1회)                                   | `[확정]` D7                                        |
| 미승인 자동 만료       | 경기 시작 시각                                                       | `[확정]` D7                                        |
| 확정 후 용병 취소 가능 | 경기 시작 24시간 전까지                                              | `[확정]` D5                                        |
| 예약 마감              | 경기 시작 2시간 전                                                   | `[제안]` 7.4                                       |
| 경기 후 처리 가능      | 종료 시각부터                                                        | `[제안]` 10.1                                      |
| 경기 후 처리 기한      | 종료 후 48시간                                                       | `[제안]` 10.2                                      |
| 평가 기한              | 참가 완료 처리 후 7일                                                | `[제안]` 12.2                                      |
| 이의제기 기한          | 노쇼·평가 반영 후 7일                                                | `[제안]` 13.2                                      |

- **"경기 시작 상한"이 필요한 이유:** 경기 10시간 전에 예약한 사람의 입금 기한을 24시간으로 두면, 경기가 끝난 뒤에도 `RESERVED` 상태가 남습니다. 지금 PRD의 만료 Cron 조건(`reserved_at < now() - 24h`)에는 이 경우가 빠져 있으므로 조건 추가가 필요합니다.
- **승인 후 취소 기한(24시간) 관련:** 경기 24시간 이내에 예약한 경우, 승인되는 순간부터 앱에서 취소할 수 없습니다. 예약 화면에서 이 사실을 미리 안내합니다 (14장).
- 모든 시각은 KST 기준입니다 (PRD 비기능 요구사항).

## 9. 취소

### 9.1 용병 취소 `[확정]` (D5, P0-14)

| 현재 상태                        | 취소 가능 시점          | 결과                                        |
| -------------------------------- | ----------------------- | ------------------------------------------- |
| `RESERVED` / `PAYMENT_SUBMITTED` | 경기 시작 전 언제든     | `CANCELLED`, 포지션 재오픈                  |
| `APPROVED`                       | 경기 시작 24시간 전까지 | `CANCELLED`, 포지션 재오픈, 주최자에게 알림 |
| `APPROVED` (24시간 이내)         | 앱에서 취소 불가        | 주최자 연락 안내 (14장)                     |

- `PAYMENT_SUBMITTED` 상태에서 취소하면 주최자에게도 알림을 보냅니다. 이미 돈을 보낸 상태라 주최자가 환불을 처리해야 하기 때문입니다 `[제안]`.
- 취소 사유 입력은 선택입니다 `[제안]`.

### 9.2 주최자 경기 취소 `[확정]` (D6, P0-12)

- 경기 시작 전이면 언제든 취소할 수 있습니다. 사유는 반드시 고릅니다: 우천 / 구장 사정 / 인원 부족 / 기타(직접 입력).
- 모든 활성 예약이 `GAME_CANCELLED`로 바뀌고 참가자에게 알림이 갑니다.
- 주최자별 취소 이력은 집계만 하고 공개하지 않습니다. 공개 여부는 베타 전에 결정합니다 `[미결]`.

### 9.3 주최자의 개별 예약 취소 `[제안]`

- 주최자는 `APPROVED`된 사람을 임의로 취소할 수 없습니다. 꼭 빼야 하는 사정이 있으면 관리자에게 요청합니다.
- 승인 전 단계에서는 거절(`REJECTED`)로 처리합니다.

### 9.4 환불 `[확정]` (PRD 2장 법적 고려)

- 환불은 모두 주최자와 용병이 직접 처리합니다. 플랫폼은 관여하지 않으며, 취소 관련 화면마다 안내 문구를 노출합니다 (14장).

## 10. 경기 후 처리

### 10.1 처리 시점 `[제안]`

- 경기 종료 시각부터 주최자 대시보드에 "참가 완료 / 노쇼" 처리 버튼이 열립니다.

### 10.2 미처리 시 `[제안]` ⚠️ PRD

- 종료 후 48시간까지 처리하지 않은 `APPROVED` 예약은 **자동으로 `ATTENDED`** 처리합니다. 이렇게 하는 이유는 두 가지입니다.
  - 주최자가 처리를 빠뜨려도 상호 평가가 막히지 않습니다.
  - 노쇼는 주최자가 적극적으로 표시한 경우에만 기록되도록 해서 억울한 노쇼를 막습니다.
- 자동 처리 6시간 전에 주최자에게 리마인드 알림을 보냅니다.
- PRD 상태 모델에는 `APPROVED → ATTENDED` 자동 전이와 해당 Cron이 없으므로 추가가 필요합니다.

### 10.3 처리 수정 `[제안]`

- 처리 기한(48시간) 안에서는 주최자가 참가 완료와 노쇼를 서로 바꿀 수 있습니다.
- 기한이 지나면 수정은 이의제기(13.2)로만 할 수 있습니다.

## 11. 노쇼

### 11.1 제재 `[확정]` (D12, D14)

| 누적 | 제재                                                                              |
| ---- | --------------------------------------------------------------------------------- |
| 1회  | 선수 카드에 노쇼 횟수 표시 + 이후 예약 시 주최자 대시보드에 "노쇼 이력 있음" 배지 |
| 2회  | 관리자 검토 대상으로 등록 → **관리자가 검토한 뒤 정지 여부 결정**                 |

### 11.2 세부 규칙

- **1회 불이익 범위** `[제안]`: MVP에서는 **배지 노출만** 합니다. 예약 우선순위를 낮추는 것은 선착순 예약 구조와 맞지 않습니다.
- **검토 대기 중 예약** `[제안]`: 허용합니다. 정지가 결정되기 전까지는 일반 사용자로 취급합니다.
- **정지 기간** `[미결]`: 영구 정지(관리자 해제)인지, 기간 정지(예: 30일)인지 결정해야 합니다.
- **노쇼 횟수 소멸** `[미결]`: 영구 누적인지, 일정 기간(예: 1년) 후 소멸인지 결정해야 합니다.
- **이의제기로 노쇼가 취소되면** `[제안]`: 노쇼 횟수를 1 줄이고 상태를 `ATTENDED`로 정정합니다. 그 결과 검토 대상 조건에서 벗어나면 검토 대상에서 해제합니다.

## 12. 평가

### 12.1 대상 `[제안]`

- 같은 경기에서 `ATTENDED` 처리된 용병끼리 평가합니다. 본인은 제외합니다.
- **주최자는 MVP에서 평가 대상과 평가자 모두에서 제외**합니다. 이유는 두 가지입니다.
  - 주최자가 직접 뛰지 않는 경우가 많습니다.
  - 주최자 신뢰도는 경기 취소 이력 등 별도 지표로 다룰 문제입니다.
- 참가자가 3명 이하인 경기는 익명성을 보장하기 어려우므로 평가 화면을 열지 않습니다 `[제안]`.

### 12.2 방식

- 항목은 매너, 실력-프로필 일치도, 시간 준수 (각 1~5점) `[확정]` (P0-8).
- 베스트플레이어 1명 투표 `[확정]`. 본인에게는 투표할 수 없습니다.
- 평가 대상 중 일부만 평가해도 됩니다 `[제안]`.
- 기한은 참가 완료 처리 후 7일. 제출 후 수정할 수 없습니다 `[제안]`.
- 평가 화면이 열리면 알림톡을 1회 보냅니다 `[제안]`.

### 12.3 공개 `[제안]`

- 평가는 **익명**입니다. 평가받은 사람에게는 누가 몇 점을 줬는지 보여주지 않습니다.
- 선수 카드의 평균 점수는 **받은 평가가 5건 이상**일 때부터 공개합니다. 그 전에는 "평가 수집 중"으로 표시합니다.
- 베스트플레이어 선정 횟수를 선수 카드에 표시합니다 (배지·랭킹은 Non-Goal).

## 13. 신고·이의제기

### 13.1 신고 `[제안]`

- 대상은 같은 경기에 참가한 용병 또는 그 경기의 주최자입니다.
- 사유: 비매너 / 폭언·폭력 / 허위 정보(급수 등) / 사기 의심 / 기타.
- 처리 결과는 경고, 정지, 기각 중 하나이고 신고자에게 결과를 알립니다. 상세 내용은 공개하지 않습니다.

### 13.2 이의제기 `[제안]`

- 대상은 본인에게 기록된 노쇼, 그리고 본인이 받은 평가입니다.
- 기한은 반영 후 7일입니다.
- 관리자 처리 목표(SLA)는 3영업일 이내입니다 `[미결]` (PRD 10장 법무·운영).
